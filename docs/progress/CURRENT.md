## Notes

- **P3 must not re-collapse the one-beat lag.** The world deliberately trails the standings: drama cues arrive at the reveal transition but avatars don't move until `phase-track` ([ADR-0009](../ADR/0009-drama-buffered-to-the-track-beat.md)). A P3 callout that fires "on the drama" fires one beat *before* the world reacts. P3's timing has to be written against the TRACK beat, not against cue arrival.
- **P3's callouts inherit P2's arbitration**, they don't invent their own ([ADR-0010](../ADR/0010-exclusive-arena-reaction-subdued-avatar-vfx.md)): one headline tier per beat, below-headline effects subdued rather than dropped. Announcing one thing while the stadium reacts to another is the failure mode.
- **Local Supabase runs on shifted ports and the shift is not in git.** Windows/Hyper-V has reserved TCP 54024–54423, which covers every default Supabase port, so `.env.local` (gitignored) points at 553xx instead while `supabase/config.toml` was deliberately left at defaults. The running stack matches `.env.local`, so it works as-is — but **do not run `supabase stop` or `supabase start`**, because a restart will bind the reserved defaults, fail, and lose the working stack. A fresh machine will need the same port shift applied by hand.
- **Headless Chromium cannot be used to measure frame budget.** It falls back to SwiftShader, idles around 16fps with `dropped 75/76`, and pins the VFX budget at `minimal` before a test starts. CDP CPU throttling is also the wrong instrument — the render loop is GPU-bound. Headed browser plus a synthetic main-thread block is the combination that works; that is how P2's exit criterion 5 was verified.

## Tech debt / known issues

- **Active streak tier does not survive a reload** (P2). [ADR-0013](../ADR/0013-persistent-vs-transient-vfx.md) classifies the streak flame as persistent, but `streakTier` accumulates from cues inside `ChoreographerState` and `streak-tier` cues fire only at the 3/5/8 milestones, so a player who reloads mid-streak loses their flame until the next milestone. Medal, leader emphasis and edge-holder turbo are standings-derived and do survive. Not fixable on the current wire: `Standing` carries `longest_streak`, not the current run, and P2's spec forbade a protocol change. **Fix:** add `current_streak` to `Standing` in whichever phase next opens the protocol, and derive the tier in `flairFor` like the rest.
- **Tied players share a compressed stack rather than offsetting in x** (P2). All-tied cases — the start line, the round-1 TRACK beat — are a tight heap of overlapping rigs. The stack is capped at `MAX_STACK_RISE` so everyone stays on canvas, which was the point, but the readable answer is two rigs per row offset in x. **Blocked on a contract change:** that requires `row` to stop meaning "unique rank within the segment", which `flairFor`'s edge-holder rule reads.
- **`TRACK_MARGIN` is the last P1 constant still sized against the deleted marker puck** (P2). The lobby grid lives entirely in the 260-unit run-off, and the run-off was sized for a 52-unit puck, not a 90-unit rig — so once `GRID_EDGE_MARGIN` reserved room to draw the rearmost rig whole, column spacing compressed from 73 to 51 units and adjacent same-row rigs now overlap by about a third of their rim. This is the same root cause as P2's Critical (a P1 constant that stopped matching what gets drawn), and it was left alone deliberately: `TRACK_MARGIN` sets the world's `minX`/`maxX`, so changing it moves the camera bounds and re-tests framing. **Fix:** widen the run-off and re-verify the camera, as its own piece of work rather than a fix tacked onto a phase close.
- **`MAX_STACK_RISE` is derived at 16:9 and applied at every aspect ratio** (P2). A deep tie puts the top rig's head at screen y +23.5 on 1920×1080 but −227.8 on 2560×1080 and −314.3 on 3440×1440. Not a regression of P2's Critical — the y-aware `offscreenPlayerIds` names those players and the readout marks them off screen — but ultrawide viewers lose the top of a deep stack to the readout instead of the canvas. **Blocked:** the honest fix needs the viewport inside `markerAnchors`, which is pure and viewport-free by contract; letting the camera widen instead is the answer the Critical's fix explicitly rejected. P6's stage view is the phase that will care.
- **The readout's off-screen marker carries no direction** (P2). It used to render a fixed `◀`, which was already wrong for players off the right and became wrong for players off the top once the check went y-aware, so it was reduced to a non-directional marker. **Fix:** have `offscreenPlayerIds` return a direction per player and render it — deferred because it changes a pure module's return type, `useWorldView`'s state shape, and every caller and test.
- **The baked-avatar texture cache is not namespaced per Pixi `Application`** (P2). Correct today — bounded at 12 entries, un-stalable because the accent is a rim rather than baked — but P6's stage view adds a second renderer, at which point the first app's GPU-bound textures get handed to the second app's sprites and the first teardown destroys textures the survivor is using. **Fix before P6:** key the cache by application and scope `clearBakedAvatars()` to it. Recorded in [ADR-0011](../ADR/0011-accent-is-a-rim-never-a-body-tint.md).
- **`turbo` at the `lean` VFX level emits particles where spec §8 says static sprite** (P2). Found by the live exit-criteria walkthrough: `ALLOWANCES.lean` has `particles: true`, and `staticDecals()` returns `[]` whenever particles are allowed, so at `lean` an edge-holder's turbo emits at `turbo: 0.5` (measured: 171 particles at exactly 0.500) and draws no static form. Not a lost signal — the turbo is still visible, at half rate — just a frame saving not taken on a device that has already shed a level, which is why it was left as built. **Fix:** give `VfxAllowance` a per-kind particle dimension and suppress turbo requests in the choreographer at `lean` in the same change, since drawing a decal *and* emitting is exactly what `staticDecals`' guard prevents. Recorded in [ADR-0012](../ADR/0012-vfx-budget-adapts-without-touching-profile.md).
- **Three of the four idle quirks have never been observed running** (P2). Only `sway` was measured live (rotation over exactly ±0.0300 rad, independent phase per rig); `bob`, `pulse` and `tilt` live in `AvatarNode.ts`'s quirk switch, which spec §9 puts outside the test boundary by design, so nothing verifies their amplitudes. A defect there is a wrong multiplier, not a crash. **Fix:** look at a lobby full of mixed characters, or lift the quirk offset computation into a pure module where it can be asserted.
- **`app/room/[code]/page.tsx:29`** — pre-existing `react-hooks/set-state-in-effect` ESLint error (`setHasSession` set synchronously inside a `useEffect`). Predates M2; not fixed during P0 because that file's session-check logic was outside P0's scope. Likely fix: derive `hasSession` from `loadSession(code)` directly (e.g. lazy `useState` initializer) instead of effect + state.
- **`npm run lint` at the repo root is red on three pre-existing files** that M2 P1 and P2 never touched. Scoped `npx eslint <files>` on touched files is clean, and that is what P2's gate used. Clean up as P1 debt rather than attributing it to whichever branch runs the gate next.
- **ESLint has no ignore for `.claude/worktrees/`** — running `npm run lint` from the repo root while a worktree is checked out under `.claude/worktrees/` double-lints that nested copy and inflates the reported problem count enormously. Not a real regression — just don't trust the count while a worktree exists. Fix: add `.claude/worktrees/**` to the ignores in `eslint.config.mjs`.
